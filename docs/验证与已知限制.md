# 验证与已知限制 · v1.2.0

离线构建后执行 **316 项隔离、无界面检查**：配置与语言 96、网格定位 56、便携数据 28、自启专项 14、壁纸毛玻璃 19、文件复制与引用 70、自定义图标和颜色 15、终极整理 18。终极整理检查包括重复运行、已有整理文件夹、同名文件自动加序号、删除全部旧胶囊后的五胶囊创建路径，以及移动失败回退。文件检查包括大于 5 MiB 的复制、副本拖出后的清理、旧版引用保护。自启只在测试目录模拟或创建测试快捷方式，不写真实用户启动文件夹。

**未进行实机 UI 验收。** 按使用者要求，没有控制其真实桌面、Explorer、任务栏或开机自启。隔离测试证明数据处理与布局计算按预期运行，不证明真实鼠标拖放、Shell 窗口层级、任务栏视觉效果或登录后出现时间。实际异常欢迎附版本、Windows 版本、复现步骤和截图反馈。

已知边界：

- **系统**：目标 Windows 11 x64 / .NET Framework 4.8；Windows 10、ARM64、定制桌面未系统验证。EXE 没有代码签名证书。
- **文件复制**：新拖入的文件不限大小，流式复制到 `Data/Capsules`；大文件需足够磁盘空间，复制同步发生在界面线程上，期间界面可能暂时不响应。文件夹仍是路径引用。旧版遗留的小文件引用会逐项迁移；大文件引用或已失效引用不会擅自更改，重新拖入即可复制。搬迁时需保留整个 `Data`。
- **拖出**：仅在 Windows 拖放返回成功的 Copy/Move 效果后移除条目。副本回收失败时保留胶囊条目，供手动核对。旧版路径引用不会删除外部原文件。不同 Explorer 目标对拖放效果的反馈尚未做真实窗口测试。
- **终极整理**：仅处理当前用户桌面顶层可见普通文件和快捷方式。重复运行复用 `胶囊整理`，重名加序号；每次成功运行新增五个胶囊，但总数仍受 32 个胶囊上限约束，需预留 5 个位置。移动失败尝试回退；若进程被强制终止或同步软件同时改动文件，需人工检查原桌面及整理文件夹。左半屏只是调整 Explorer 窗口位置，不创建 Snap 分组。
- **桌面网格**：Shell 图标网格读取失败时回退固定网格；桌面活动时约 2 秒刷新。缩放、多显示器和图标重叠的实际表现未在用户电脑验收。
- **自启**：用户启动文件夹快捷方式在程序运行时登记并读回核验；系统设置、组织策略或 Windows 的启动排队可能阻止或延迟真正执行。改名升级要使用完整 ZIP、保留 `Data` 并运行新 EXE。停用前选“清理自启并退出”；误删程序后，可从 `shell:startup` 手动删除仅属于本程序的快捷方式。
- **毛玻璃和任务栏**：胶囊面板取样静态壁纸，不实时模糊其他窗口或动态壁纸；任务栏效果依赖 ExplorerTAP、Windows 版本及其他美化软件。离屏像素测试不等于屏幕观感验收。
- **轻量化**：披露的是发布文件大小；没有跨设备 CPU、内存或启动速度基准数据。

日志：`Data/Logs/startup.log`、`Data/Logs/taskbar.log`。日志只能证明调用和运行过程，不能证明视觉效果；公开前请检查个人目录路径。

# Validation and known limits · v1.2.0

The offline build passed **316 isolated headless checks**: core configuration and language 96, grid placement 56, portable data 28, startup 14, wallpaper glass 19, file copy/reference handling 70, custom icons/colors 15, and Ultimate Organizing Mode 18. Organizing cases include repeated runs, an existing destination folder, numbered filename collisions, creating five capsules after all older capsules were deleted, and rollback on move failure. File checks cover copies over 5 MiB, cleanup after dragging stored entries out, and protection of legacy references. Startup tests use in-memory adapters or shortcuts inside test directories; they never write the real user Startup folder.

**No live UI acceptance test was performed.** At the user's request, development did not control their real desktop, Explorer, taskbar, or startup registration. Isolated checks support data handling and layout calculations, but do not prove mouse drag/drop in Explorer, Shell layering, taskbar appearance, or sign-in timing. Please report real-use problems with app and Windows versions, steps, and screenshots.

Known limits:

- **System**: Target is Windows 11 x64 / .NET Framework 4.8. Windows 10, ARM64, and customized desktops are not systematically verified. The EXE is unsigned.
- **File copy**: Newly imported files of any size are streamed into `Data/Capsules`. Large files need disk space and synchronous copying may temporarily block the UI. Folders remain path references. Existing small-file references migrate gradually; large or missing legacy references are left unchanged unless reimported. Preserve all of `Data` when moving the app.
- **Drag out**: Entries are removed only after Windows drag/drop returns an accepted Copy/Move result. If recycling a stored copy fails, its capsule entry is retained for manual checking. Legacy references never delete external originals. Actual feedback from different Explorer drop targets has not been tested in a real window.
- **Ultimate Organizing Mode**: Only visible ordinary top-level files and shortcuts from the current user's Desktop are moved. Repeated runs reuse `胶囊整理` and number collisions. Each successful run creates five new capsules, subject to the 32-capsule limit; leave five free slots. Failed moves attempt rollback. After a forced exit or concurrent sync changes, manually check both locations. Left-half placement moves/resizes Explorer; it does not create a Snap group.
- **Desktop grid**: A fixed grid is used if Shell icon-grid reading fails. It refreshes about every two seconds while the desktop is active. Real display scaling, multiple monitors, and overlaps were not accepted on the user's computer.
- **Startup**: A current-user Startup shortcut is registered and read back while the app runs. System settings, policy, or Windows Startup scheduling may prevent or delay actual execution. Upgrading from the old name requires the full ZIP, preserved `Data`, and one launch of the new EXE. Choose “Clean startup and exit” before removal; if already removed, delete only this app's shortcut from `shell:startup`.
- **Glass and taskbar**: The panel samples static wallpaper; it does not live-blur other windows or moving wallpaper. Taskbar effects depend on ExplorerTAP, the Windows version, and other taskbar tools. Offscreen pixel tests are not visual acceptance.
- **Small size**: Published measurements describe file size, not cross-device CPU, memory, or startup-time benchmarks.

Logs: `Data/Logs/startup.log` and `Data/Logs/taskbar.log`. Logs describe calls and runtime events, not visual correctness. Check personal paths before sharing them.
