# 验证与已知限制 · v1.2.1

离线构建后执行 **348 项隔离检查**：配置与语言 96、网格定位及尺寸 61、便携数据 28、自启专项 15、壁纸毛玻璃 19、文件复制与引用 76、自定义图标/矢量图、四个右键入口与弹窗 30、终极整理 23。前一候选版另通过 42 项便携集成检查；v1.2.1 本轮按用户要求没有运行会显示窗口的集成测试。测试不写真实用户启动文件夹。

**未进行实机 UI 验收。** 按使用者要求，没有控制其真实桌面、Explorer、任务栏或开机自启。隔离测试证明数据处理与布局计算按预期运行，不证明真实鼠标拖放、Shell 窗口层级、任务栏视觉效果或登录后出现时间。实际异常欢迎附版本、Windows 版本、复现步骤和截图反馈。

已知边界：

- **系统**：目标 Windows 11 x64 / .NET Framework 4.8；Windows 10、ARM64、定制桌面未系统验证。EXE 没有代码签名证书。
- **文件复制**：新拖入的文件不限大小，流式复制到 `Data/Capsules`；大文件需足够磁盘空间，复制同步发生在界面线程上，期间界面可能暂时不响应。同一路径重复导入会安全更新副本；失败时保留旧副本。文件夹仍是路径引用。旧版遗留的小文件引用会逐项迁移；大文件引用或已失效引用不会擅自更改，重新拖入即可复制。搬迁时需保留整个 `Data`。
- **拖出**：仅在 Windows 拖放返回成功的 Copy/Move 效果后移除条目。副本回收失败时保留胶囊条目，供手动核对。旧版路径引用不会删除外部原文件。不同 Explorer 目标对拖放效果的反馈尚未做真实窗口测试。
- **终极整理**：仅处理当前用户桌面顶层可见普通文件和快捷方式。重复运行复用 `胶囊整理`，重名加序号；每次成功运行新增五个胶囊，但总数仍受 32 个胶囊上限约束，需预留 5 个位置。移动失败尝试回退；若进程被强制终止或同步软件同时改动文件，需人工检查原桌面及整理文件夹。左半屏只是调整 Explorer 窗口位置，不创建 Snap 分组。
- **桌面网格与尺寸**：启动和每次新建胶囊时读取 Shell 图标尺寸并调整全部胶囊，桌面活动时约 2 秒刷新；默认图案为内置矢量路径，无额外大位图。Shell 读取失败时回退固定网格和中等尺寸。实际 Ctrl+滚轮、缩放、多显示器表现仍需用户验收。
- **胶囊右键**：更名、改色、改透明度、删除为四个单独入口，分别打开只处理当前胶囊的窗口。改色只适用于默认图案；透明度也适用于自定义图片，0% 表示不透明、100% 表示完全透明。真实鼠标菜单交互仍需用户验收。
- **自启**：用户启动文件夹快捷方式在程序运行时登记并读回核验；系统设置、组织策略或 Windows 的启动排队可能阻止或延迟真正执行。改名升级要使用完整 ZIP、保留 `Data` 并运行新 EXE。停用前点击胶囊管理窗口底部的关闭自启链接，然后从托盘退出；误删程序后，可从 `shell:startup` 手动删除仅属于本程序的快捷方式。
- **毛玻璃和任务栏**：胶囊面板取样静态壁纸，不实时模糊其他窗口或动态壁纸；任务栏效果依赖 ExplorerTAP、Windows 版本及其他美化软件。离屏像素测试不等于屏幕观感验收。
- **轻量化**：披露的是发布文件大小；没有跨设备 CPU、内存或启动速度基准数据。

日志：`Data/Logs/startup.log`、`Data/Logs/taskbar.log`。日志只能证明调用和运行过程，不能证明视觉效果；公开前请检查个人目录路径。

# Validation and known limits · v1.2.1

The offline build passed **348 isolated checks**: core configuration/language 96, grid/icon sizing 61, portable data 28, startup 15, glass 19, file copy/reference handling 76, custom/vector icons, four context-menu entries and dialogs 30, and Ultimate Organizing Mode 23. A previous candidate also passed 42 portable integration checks. For v1.2.1, window-opening integration tests were not rerun at the user's request. Startup tests never write the real Startup folder.

**No live UI acceptance test was performed.** At the user's request, development did not control their real desktop, Explorer, taskbar, or startup registration. Isolated checks support data handling and layout calculations, but do not prove mouse drag/drop in Explorer, Shell layering, taskbar appearance, or sign-in timing. Please report real-use problems with app and Windows versions, steps, and screenshots.

Known limits:

- **System**: Target is Windows 11 x64 / .NET Framework 4.8. Windows 10, ARM64, and customized desktops are not systematically verified. The EXE is unsigned.
- **File copy**: Newly imported files of any size are streamed into `Data/Capsules`. Large files need disk space and synchronous copying may temporarily block the UI. Reimporting the same path safely refreshes its copy; failure preserves the old copy. Folders remain path references. Existing small-file references migrate gradually; large or missing legacy references are left unchanged unless reimported. Preserve all of `Data` when moving the app.
- **Drag out**: Entries are removed only after Windows drag/drop returns an accepted Copy/Move result. If recycling a stored copy fails, its capsule entry is retained for manual checking. Legacy references never delete external originals. Actual feedback from different Explorer drop targets has not been tested in a real window.
- **Ultimate Organizing Mode**: Only visible ordinary top-level files and shortcuts from the current user's Desktop are moved. Repeated runs reuse `胶囊整理` and number collisions. Each successful run creates five new capsules, subject to the 32-capsule limit; leave five free slots. Failed moves attempt rollback. After a forced exit or concurrent sync changes, manually check both locations. Left-half placement moves/resizes Explorer; it does not create a Snap group.
- **Desktop grid and size**: At launch and whenever a capsule is added, the app reads the Shell icon size and resizes all capsules. It refreshes about every two seconds while the desktop is active. Default artwork uses vector paths, with no large bitmap asset. If Shell reading fails, a fixed grid and medium icon size are used. Actual Ctrl+wheel, DPI, and multi-monitor behavior still need user acceptance.
- **Capsule right-click**: Rename, color, transparency, and delete are separate commands and dialogs for one capsule. Color changes only default artwork. Transparency also works for custom images: 0% is opaque, 100% is invisible. Live pointer/menu behavior still needs user acceptance.
- **Startup**: A current-user Startup shortcut is registered and read back while the app runs. System settings, policy, or Windows Startup scheduling may prevent or delay actual execution. Upgrading from the old name requires the full ZIP, preserved `Data`, and one launch of the new EXE. Before removal, turn off startup using the link at the bottom of Capsule Manager, then exit from the tray; if already removed, delete only this app's shortcut from `shell:startup`.
- **Glass and taskbar**: The panel samples static wallpaper; it does not live-blur other windows or moving wallpaper. Taskbar effects depend on ExplorerTAP, the Windows version, and other taskbar tools. Offscreen pixel tests are not visual acceptance.
- **Small size**: Published measurements describe file size, not cross-device CPU, memory, or startup-time benchmarks.

Logs: `Data/Logs/startup.log` and `Data/Logs/taskbar.log`. Logs describe calls and runtime events, not visual correctness. Check personal paths before sharing them.
